## What is being "implemented"

This feature modifies a **Claude Code skill**, not application code. The deliverable is edits to the markdown that instructs the driver agent, plus possibly a shell script and a new reference file — there is no compiled program, no service, no database. "Runtime behavior" means how the driver agent behaves when it follows these instructions; "resilience/structure" concerns apply to the instructions and to the driver's git-history handling.

- **Target skill:** `han-coding/skills/implement-work-items/` — `SKILL.md` (Steps 1–4 + Halt Procedure, ~330 lines), `references/` (`build-report-contract.md`, `foreground-handoff-protocol.md`, `human-review-capture.md`, `no-output-completion.md`, `review-verdict-contract.md`), `scripts/detect-driver-context.sh` (existing deterministic context detector: git availability, current/default branch, uncommitted-file list, manifest-inferred commands).
- **Operator doc (must stay in sync):** `docs/skills/han-coding/implement-work-items.md` — its TL;DR, "In more detail," and YAGNI sections currently describe the driver as **single-pass, no-resume, absolute halt**; those paragraphs are the ones this feature inverts and must be rewritten.

## Tech stack / conventions

- **Repo:** `han` — a Claude Code plugin suite (markdown skills + agent definitions). No app runtime.
- **Skill authoring rules (the "coding standard" for this work):** `han-plugin-builder/skills/guidance/references/skill-building-guidance/` — the load-bearing ones for this feature:
  - `hardening-fuzzy-vs-deterministic.md` — **central to the approach.** Deterministic operations (scan branch log for progress markers, compute changed-file sets from a baseline commit, resolve a commit reference, detect fresh-vs-resume) belong in `scripts/`; judgment (classify resume state, surface-and-ask, present the recovery menu) stays in SKILL.md. Split hybrid steps.
  - `script-execution-instructions.md` — scripts invoked as numbered prose with `${CLAUDE_SKILL_DIR}/scripts/...`, never fenced code blocks; scripts stay out of `allowed-tools` (prefix matching can't resolve the expanded path); each skill owns its scripts.
  - `progressive-disclosure.md`, `skill-reference-files.md` — three-level architecture; a large new mechanic (the durable-record read/detect/integrity logic) is a candidate for its own reference file rather than bloating SKILL.md.
  - `optional-git-repositories.md`, `graceful-degradation.md`, `context-hygiene.md` — relevant to the git-history dependency, hook-rejection failure class, and the compaction/commit-boundary self-check.
- **Commit convention:** Conventional Commits (`type(scope): subject`), enforced across the repo; the skill itself detects the target repo's convention at run time (SKILL.md Step 2.2). The driver's own bookkeeping commits must conform (spec D20/T1).
- **Writing voice:** `docs/writing-voice.md` — no em-dashes, direct second person; applies to the operator doc rewrite.
- **Contributor process:** `CONTRIBUTING.md` (§"Adding a skill", §"Editing an existing long-form doc", §"Reviewing your own changes").

## Explicit gaps (searched, not found)
