# Discovery Notes: Non-code, meta, and non-deliverable work items

Single source of truth for project context across the planning team. **Read this first; do not re-grep for what is already here.** Search further only for what your domain specifically needs that these notes do not cover, and cite what you read.

## Nature of the change

This is a **markdown skill-authoring change**, not application code. The "implementation" is edits to two Claude Code skill definitions (`SKILL.md` + `references/*.md`), one classification catalog, one work-item template, and two long-form docs. There is **no compiler, no application runtime, and no automated test harness for skill behavior**. The immediate predecessor feature (`autonomous-driver-hitl-support`) established the verification model this plan will inherit: **read-the-file contract checks (C#) plus manual dry-runs (A#)** against the skills' contracts. Current branch: `feat/autonomous-driver-core-loop`.

The feature extends two coordinating skills:
- **Producer** — `plan-work-items` (classifies a plan into work items, emitting the per-item markers).
- **Driver** — `implement-work-items` (validates, builds, verifies, reviews, commits each item).

The producer→driver marker vocabulary is a **shared contract**; the spec (D11) commits that any change to the refusal set is applied to both skills in one commit as a maintenance convention (no cross-skill enforcement machinery — explicitly out of scope).

## Tech stack

- Claude Code plugin suite; skills are markdown (`SKILL.md`) with `references/*.md` and occasional `scripts/*.sh`.
- Repo is git; shell is `fish`; no package manager, build tool, or test runner is involved in the skill definitions themselves.
- `han-coding/skills/implement-work-items/scripts/detect-driver-context.sh` exists (driver context detection) — the only script in either skill.

## Authoring standards (the "coding standards" analog)

- `docs/writing-voice.md` — voice profile every doc/skill follows: **no em-dashes**, no flattery/hype, direct second person, banned words (`leverage`, `utilize`, `just`, `actually`, `robust`, `Importantly`).
- `CONTRIBUTING.md` — contributor guide; the **coverage rule** (every skill and agent gets a long-form doc) is enforced here and in `docs/templates/coverage-rule.md`.
- `docs/templates/` — `skill-long-form-template.md`, `agent-long-form-template.md`, `coverage-rule.md`.
- `han-plugin-builder/skills/guidance/references/` — the plugin-authoring guidance the spike/edit-existing flows link as item references (`skill-building-guidance/`, `agent-building-guidelines/`, `plugin-entity-taxonomy.md`, `claude-marketplace-and-plugin-configuration/`, `iterative-plugin-development.md`, `specialization-and-model-selection.md`). Spec D5/D15: guidance is reference-only, linked on the item, never the implementer.

## Format precedent

Four prior implementation plans in `docs/plans/` share the format the PM template prescribes:
- `docs/plans/autonomous-driver-hitl-support/feature-implementation-plan.md` — **the closest precedent and the direct predecessor** whose HITL normalization this feature builds on. Same nature (two skill definitions + reference files + producer catalog, no application code, no test harness). Its decomposition style is the model: generalize-the-contract-first → atomic SKILL.md edit (Step 1.7 + Step 3 as one edit) → co-land the companion catalog change → long-form-docs-and-voice pass → verification pass (C# read-the-file + A# dry-runs). Uses `D-N` decisions with inline `([D-N](artifacts/implementation-decision-log.md#...))` links; RAID risks are the compaction budget, hand-off resume reliability, etc.
- `docs/plans/autonomous-driver-core-loop/feature-implementation-plan.md` — the core-loop feature (current branch namesake).
- `docs/plans/autonomous-driver-per-item-skill-selection/feature-implementation-plan.md`, `docs/plans/canonical-evidence-resource/feature-implementation-plan.md` — additional precedent.

**Compaction budget is a known constraint** carried from the HITL plan: the driver `SKILL.md` body is at the post-compaction context cap (~5k), so new detail is pushed to reference files rather than inlined. This feature adds driver validation (four refusals) and new build/review shapes — a real budget concern for the SKILL.md edit.
