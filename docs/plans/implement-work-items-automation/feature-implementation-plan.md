# Feature Implementation Plan: implement-work-items Driver Automation and Resumability Hardening

Move the driver's deterministic clerical work (record/branch/dir creation, record writes and their git commits with resume-marker trailers, base refresh, run-state reconstruction, tree-state checks) out of `SKILL.md` prose and into the three bash scripts, so on the happy path the driver runs git only to commit item code. Drop the expected-paths scope mechanic, consolidate the reference files by actor, persist resume-critical state in committed artifacts, and retire the `no-commit-done` terminal state. Posture: a self-contained change to one in-repo skill, built script-and-harness-first, verified by the skill's own `*.test.sh` harnesses (the only automated gate) then a single-session dogfood, rolled back with `git revert`.

## Outcome

When this plan is executed, `han-coding/skills/implement-work-items/`'s three bash scripts own the run's deterministic version-control, record-and-file, and state-discovery work: `write-run-record.sh` creates the record area and branch, writes each record entry and commits it atomically with the resume-marker trailers, and returns the item's baseline; `detect-driver-context.sh` performs its own bounded base refresh and reports freshness; `scan-run-history.sh` reconstructs run state (including the newly-durable pre-work decisions and fix-round count) from committed artifacts only. `SKILL.md`'s driver prose shrinks to judgment work — building, reviewing, gating, deciding, halting — and runs git itself only to commit item code on the happy path. The `references/` directory is consolidated to an actor-labeled scheme, the `no-commit-done` state is gone from both scripts, the expected-paths mechanic is removed from the driver's use, and the long-form doc at `docs/skills/han-coding/implement-work-items.md` is updated in the same change.

## Context

- **Driving constraint:** The second-run operator retrospective (`docs/research/implement-work-items-second-run-feedback.md`) flagged the driver's manual bookkeeping as the dominant friction — verbose, error-prone, repeated per item — and named a concrete resume-corruption hazard from editing the resume machinery mid-run. This plan removes that toil and hardens resume before the next run reproduces the friction.
- **Stakeholders:** The **operator** (fewer manual git steps, cleaner resume, fewer transcription errors); the **driver agent** (a smaller instruction surface, correctness by construction rather than by prose discipline); **future skill authors** (the two-actor reference scheme and the single `write_and_commit` paved path are patterns they will copy).
- **Future-state concern:** The scripts become the load-bearing correctness surface for resume integrity, and the `*.test.sh` harnesses are the only automated gate (no CI). After ship, the harnesses must be kept green as the sole regression net; if CI is later added, the manual gate should become automated ([D-7](artifacts/implementation-decision-log.md#d-7-buildverify-sequence-single-session-dogfood-and-git-revert-rollback)).
- **Out-of-scope boundary:** Review-quality process changes (tiered review, confirmation-only re-reviews, a standing compactness lens — spec D13); the flat review-dispatch / nested-agent-hang harness workaround (separately deferred); de-bloating `SKILL.md` below its line ceiling (spec Out of Scope — this change is expected net-neutral-to-negative on line count, [D-8](artifacts/implementation-decision-log.md#trivial-decisions)); changing the work-items producer's output (this feature depends only on the item type field the producer already emits).

## Implementation Approach

The change is scoped to five artifacts inside one skill directory (`.discovery-notes.md` §Code touch points). The whole machinery was built and hardened in the last 90 days, so the git history is current precedent for how each mechanic was introduced; this plan extends existing primitives rather than introducing new frameworks.

### Architecture and Integration Points

The skill's shape is a driver agent (`SKILL.md`) plus three bash scripts and a set of markdown references. This change shifts the driver/tooling boundary: deterministic git/record/state work moves from `SKILL.md` prose into the scripts (spec D1), leaving the driver its judgment work plus the one happy-path git action — committing item code.

- **`write-run-record.sh`** grows from an append-only, never-runs-git writer into the run's bookkeeping owner: it creates the record area and branch, commits each write with the resume trailers, asserts tree state, and returns the item's baseline. Every git-touching subcommand routes through one internal `write_and_commit` helper that folds write→stage→no-op-check→commit→trailer-readback→rollback into a single atomic path ([D-1](artifacts/implementation-decision-log.md#d-1-one-write_and_commit-helper-is-the-atomic-paved-path-for-every-bookkeeping-write)). Setup and lifecycle writes are idempotent — `init` is a create-or-switch, `log start-of-item` re-emits an existing baseline rather than duplicating it ([D-2](artifacts/implementation-decision-log.md#d-2-idempotent-record-writes-and-baseline-re-emission)). The opening `init` commit is the one explicit exception to narrow staging, co-committing the record and the enumerated planning artifacts ([D-12](artifacts/implementation-decision-log.md#d-12-opening-co-commit-is-an-explicit-exception-to-narrow-staging)).
- **`detect-driver-context.sh`** stops being read-only: it performs its own base refresh in a single bounded attempt and reports freshness, skipping the fetch on a resume ([D-4](artifacts/implementation-decision-log.md#d-4-bounded-single-attempt-self-fetch-with-resume-before-fetch-classification)), and gains the expanded base candidates (`dev`/`develop`/`development`/`trunk`) ranked below the mainline names (spec D12).
- **`scan-run-history.sh`** extends reconstruction to the newly-durable state (pre-work decisions, fix-round count), sources resume-critical reads from `git show HEAD:` only ([D-5](artifacts/implementation-decision-log.md#d-5-resume-critical-reads-gate-on-committed-artifacts-marker-last-ordering-enforced-by-construction)), resolves an audit's `done` through the same `ITEM_RESOLVED` trailer path a code item uses, and drops the `no-commit-done`/`done-no-commit` token and state ([D-6](artifacts/implementation-decision-log.md#d-6-retire-no-commit-done-audit-done-resolves-against-its-confirmation-record-commit)).
- **`references/`** consolidates to the actor-labeled scheme: a driver-facing and a sub-agent-facing hand-off reference (the required return format lives sub-agent-facing, the parse/halt logic driver-facing), the rest renamed, `no-output-completion.md` shrunk and folded, and `re-grounding-routine.md` gutted to its residual reload-instructions driver step ([D-11](artifacts/implementation-decision-log.md#d-11-two-actor-reference-split-return-format-ownership-and-the-enumerated-end-state-file-list)).
- **`SKILL.md`** removes the moved prose (per-item commit orchestration, clean-tree assertions, the detect→fetch→re-detect dance, expected-paths validation/scope/coherence keying, improvised re-grounding steps 1-3, `no-commit-done` handling) and routes to the two references plus tooling. The body stays over the 500-line ceiling, which is tolerated for this change ([D-8](artifacts/implementation-decision-log.md#trivial-decisions)); `allowed-tools` is narrowed toward observed git usage plus script execution ([D-10](artifacts/implementation-decision-log.md#trivial-decisions)).
- **`docs/skills/han-coding/implement-work-items.md`** is updated in the same change (CONTRIBUTING doc-sync); it currently documents the `done-no-commit` outcome that [D-6](artifacts/implementation-decision-log.md#d-6-retire-no-commit-done-audit-done-resolves-against-its-confirmation-record-commit) retires.

### Runtime Behavior

On the happy path the driver's only git action is the item's code commit; the tooling owns setup and every bookkeeping commit, and recovery-time tree resets stay the driver's under operator confirmation (spec D5). Resume reconstructs run state from committed artifacts in one tooling pass at every re-entry site (spec D4), and a durable marker is never committed before the artifact it attests, so the only reachable partial state on a mid-step death is artifact-present-marker-absent, read as in-progress ([D-5](artifacts/implementation-decision-log.md#d-5-resume-critical-reads-gate-on-committed-artifacts-marker-last-ordering-enforced-by-construction)). Reconstruction reads only `git show HEAD:` for resume-critical fields, so an uncommitted decision or marker is never mistaken for durable state.

## Testing Strategy

The observable-behavior test plan is owned by `test-engineer` and detailed in [test-plan.md](artifacts/test-plan.md) (17 cases T1–T15 plus 5 skips S1–S5); this section references it rather than duplicating it.

- **Observable behaviors to test:** the writer's atomic write-and-commit (a failed commit leaves the record unchanged), narrow staging, baseline trailer/ref return, terminal-last ordering, idempotent re-entry; the detector's bounded self-fetch (effect asserted via post-fetch ref state, not a mocked `git fetch`) and resume-skip; the scanner's decision/fix-round reconstruction, audit-`done` parity with a code item, `no-commit-done` absence, and the uncommitted-is-not-durable negative case.
- **Test doubles posture:** real git sandboxes as the fixture (the collaborator is git itself, so a query stub is not meaningful); a real rejecting `.git/hooks/pre-commit` shim for the failing-commit cases; a local bare repo as the fetch "remote" with a controlled-hang double (a blocking wrapper or a very short deadline), never a real timed sleep, to keep the harness fast and deterministic ([test-plan.md](artifacts/test-plan.md) T2/T11).
- **Edge cases requiring coverage:** the case-17 T#-contradiction — the existing `scan-run-history.test.sh` case 17 asserts the working-tree fallback *does* populate items, which contradicts T1's committed-only boundary; it is retargeted to the committed-only boundary for resume-critical fields, not silently dropped ([D-5](artifacts/implementation-decision-log.md#d-5-resume-critical-reads-gate-on-committed-artifacts-marker-last-ordering-enforced-by-construction), [test-plan.md](artifacts/test-plan.md) T9).
- **Test levels:** unit (bash harness) reaches everything except D7 (reviewer judges scope from the diff), which has no script entry point and is exercised end-to-end only in the dogfood ([test-plan.md](artifacts/test-plan.md) S1). Verification is two-phase: **Phase 1** — all `*.test.sh` harnesses green before any dogfood run (the only automated gate; the harnesses carry the correctness burden against crafted repos, needing no live run of the machinery being changed); **Phase 2** — a dogfood scoped to a single continuous session with no cold stop/resume across the migration boundary, proving the driver-level integration, D7's scope judgment, and the operator-facing UX ([D-7](artifacts/implementation-decision-log.md#d-7-buildverify-sequence-single-session-dogfood-and-git-revert-rollback)).

## Security Posture

`adversarial-security-analyst` (R1) found the two prior bug classes reappearing at the new sinks D5/D10/D11 introduce. The theme: the repo already owns both guard primitives (`require_single_line` at `write-run-record.sh:33-40`; `--end-of-options`/`--` ref pinning at `detect-driver-context.sh:39-41` and `scan-run-history.sh:94,106`); the recurring bug is not applying an owned primitive at each new sink. The plan commits to applying them at every new sink ([D-3](artifacts/implementation-decision-log.md#d-3-extend-the-existing-input-guards-to-every-new-git-sink), [D-5](artifacts/implementation-decision-log.md#d-5-resume-critical-reads-gate-on-committed-artifacts-marker-last-ordering-enforced-by-construction)).

| ID | Threat vector | Mitigation |
|----|---------------|------------|
| SEC-001 | A newline or control character in an item ID or free-text value forges a grammar-valid commit trailer or splits an appended record line | Run `require_single_line` on every value reaching a commit message, trailer, or appended record line; regex-validate any item ID reaching a trailer (`^W-[0-9]+$`) ([D-3](artifacts/implementation-decision-log.md#d-3-extend-the-existing-input-guards-to-every-new-git-sink)) |
| SEC-002 | `git add` of item paths admits option-injection (`--all`) or pathspec-magic (`:(exclude)`), escaping D5's narrow staging | `--` before pathspecs; refuse a leading `-` or `:`; reuse `normalize_path` + the `../`/absolute refusal to confine staging to the intended area ([D-3](artifacts/implementation-decision-log.md#d-3-extend-the-existing-input-guards-to-every-new-git-sink)) |
| SEC-003 | The working-tree ledger fallback (`scan-run-history.sh:146-152`) satisfies a resume-critical read once D10/D11 state lives there, admitting uncommitted state as durable | Gate resume-critical reconstruction on `git show HEAD:` only; preserve the `:138-140` traversal refusal (honors T1) ([D-5](artifacts/implementation-decision-log.md#d-5-resume-critical-reads-gate-on-committed-artifacts-marker-last-ordering-enforced-by-construction)) |
| SEC-004 | The new D3 fetch and D5 branch commands miss the sibling scripts' ref pinning, admitting a ref value read as a git option | Inherit `--end-of-options`/`--` pinning; validate branch names with `git check-ref-format --branch` ([D-3](artifacts/implementation-decision-log.md#d-3-extend-the-existing-input-guards-to-every-new-git-sink)) |
| SEC-005 | The new D10 decision and D11 marker free-text fields forge a grammar-valid ledger line | Apply `require_single_line` to the new free-text fields, same as every other appended value ([D-3](artifacts/implementation-decision-log.md#d-3-extend-the-existing-input-guards-to-every-new-git-sink)) |

## On-Call Resilience Posture

`on-call-engineer` (R1) found the write→commit seam and the folded-in fetch as the resilience surface; the commitments below map to the seam's data-integrity, idempotency, and timeout rows. OCE-009 (existing `die`-to-stderr surface is adequate) confirmed no new telemetry is warranted (see Deferred YAGNI). Application-source level only — this is a local dev-tool skill with no deploy, observability, flag, scale, or cost surface (see Operational Readiness omission below).

- **Timeouts and deadlines:** the detector's self-fetch is a single bounded wall-clock attempt (`timeout <N>s git fetch`), a literal deadline; expiry emits `fetch-status: failed` and folds into the spec's stale-counts / no-recommendation base prompt (OCE-004, [D-4](artifacts/implementation-decision-log.md#d-4-bounded-single-attempt-self-fetch-with-resume-before-fetch-classification)).
- **Retry strategy:** none — one fetch attempt, no backoff; retry/backoff is deferred absent measured transient-failure frequency (OCE-004 recommended path, see Deferred YAGNI).
- **Idempotency:** `init` is a create-or-switch (an existing branch is switched to, not re-created, and an existing opening is not re-committed); `log start-of-item` re-emits an existing baseline rather than appending a duplicate entry or creating a duplicate baseline commit, guarding the writer-dies-after-commit-before-return path (OCE-002, [D-2](artifacts/implementation-decision-log.md#d-2-idempotent-record-writes-and-baseline-re-emission)).
- **Data integrity:** write and commit are one atomic action — a hook-rejected commit rolls the record file back to its pre-write content (reusing `write_atomic`) and resets the staged path, so no torn state remains; a commit with nothing staged is classified as an idempotent no-op (`git diff --cached --quiet -- "$rec"`) and a commit that fails with content staged is an unambiguous rejection surfaced as a resumable stop; staging is scoped to the exact record file so a formatter-on-save edit is neither swept in nor a false halt; the commit's trailers are read back after committing to catch a trailer-stripping hook (OCE-001/003/007/008, [D-1](artifacts/implementation-decision-log.md#d-1-one-write_and_commit-helper-is-the-atomic-paved-path-for-every-bookkeeping-write)).
- **Ordering / marker safety:** marker-last ordering (spec D14) is enforced by construction across the two-actor split — the terminal/lifecycle marker is committed only after the artifact it attests, with the reader's default-deny as the crash-time backstop, not the sole defense; the tool optionally verifies the backing commit resolves before writing a terminal marker (OCE-006, [D-5](artifacts/implementation-decision-log.md#d-5-resume-critical-reads-gate-on-committed-artifacts-marker-last-ordering-enforced-by-construction)).
- **Observability of failure paths:** no new telemetry — the existing `die`-to-stderr surface is adequate for a fail-loud local script (OCE-009, see Deferred YAGNI).

## Deferred (YAGNI)

### Retry/backoff on the detector self-fetch
- **Why deferred:** Evidence test — no measured metric or incident shows transient fetch failures occurring at a frequency that retry would address; the spec asks only for a bounded deadline, and a single bounded attempt satisfies that evidence (simpler-version test). Adding retry now is "for future flexibility" without measured pressure.
- **Reopen when:** transient fetch failures are observed frequent in real runs.
- **Source:** R1 on-call-engineer (OCE-004 recommended path).

### Configurable fetch-deadline knob
- **Why deferred:** Simpler-version test — a literal deadline value satisfies the same evidence; no caller sets a non-default value, and the spec's OI-1 already owns the "make the refresh suppressible" question, so a configuration surface here would duplicate an open item (named anti-pattern: speculative configuration knob).
- **Reopen when:** OI-1 resolves toward operator-facing refresh control, or a run demonstrably needs a different deadline than the literal.
- **Source:** R1 on-call-engineer.

### Pruning old per-round review records
- **Why deferred:** Simpler-version test — not pruning is strictly simpler (pruning adds a delete step and a retention policy); each round's record is committed when written and retained as history, and no evidence calls for a cleanup step ([D-9](artifacts/implementation-decision-log.md#trivial-decisions)). Recorded as retain-all, not "retain everything," so it is not cited as an unbounded-retention precedent.
- **Reopen when:** the accumulated review records under `reviews/` are shown to cause a concrete problem (repo size, resume-scan cost) in a real run.
- **Source:** R1 junior-developer (JD-9).

### New writer telemetry / structured logging
- **Why deferred:** Evidence test — the existing `die`-to-stderr surface is adequate for a fail-loud local script; no failure mode is going unobserved that structured logging would surface (named anti-pattern: speculative observability for a local tool with no telemetry destination).
- **Reopen when:** a failure class is found that the `die`-to-stderr surface cannot make legible.
- **Source:** R1 on-call-engineer (OCE-009).
