# Feature Technical Notes: Autonomous Driver Human-in-the-Loop Support

## T1: Normalized review verdict and per-source severity mapping

- **Context:** The Primary Flow and Coordinations commit the driver to evaluating one gate against one verdict shape "regardless of source," to supplying each source the reference material it needs, and to treating an unmappable output as an untrustworthy verdict. That behavior is only correct because a concrete normalized verdict shape, a per-source severity mapping, a per-source coverage attestation, and a reference-material requirement exist; without them a non-code reviewer's output cannot be judged against the same at-or-above-threshold gate as a code review, or is structurally valid but unreliable.
- **Technical detail:** The normalized verdict carries the sections the driver already parses fail-closed for `code-review` — a recommendation line, a coverage attestation, findings at or above the gate threshold (each with a tier, a location, and a one-line claim), below-threshold counts, and a durable-record path — generalized so any review source fills it.
  - **Severity mapping.** Each source's native severities map into the driver's Critical / Warning / Suggestion tiers so the one threshold applies uniformly:
    - `code-review` — identity: Critical / Warning / Suggestion map to themselves; its advisory YAGNI class stays non-gating; each `SEC-###` finding carries its own tier and gates by that tier (unchanged from the current contract).
    - `information-architect` — Blocks comprehension → Critical; Degrades comprehension → Warning; Friction → Suggestion; Polish → below-threshold.
    - `content-auditor` — it emits no severity tiers, only Present / Correctly Removed / Missing; each Missing fact is a gate-blocking finding at Warning (there is no Critical escalation — `content-auditor` produces no field to derive one from, and at the default `warning` gate every Missing already blocks); Present and Correctly Removed are not findings.
    - a human read — the operator states each finding's tier directly in Critical / Warning / Suggestion terms, confirmed against the active threshold before the verdict is finalized.
  - **Coverage attestation, per source.** The existing halt on a missing or partial-panel coverage section is `code-review`-panel-shaped; it is generalized so a single review agent attests it ran to completion and a human read attests the operator reviewed the change. The halt fires only when the attestation is absent, not when it lacks panel-specific language.
  - **Location.** A finding's location is a `file:line` when the reviewed artifact is code and a document anchor (a section or heading, or "document-wide") when it is prose, so a whole-document or missing-section finding has a valid location.
  - **Reference material.** The dispatch supplies each source the material it needs to produce a reliable verdict: the item and the spec sections it references for every source, and, for a content audit, the prior version of the document being edited (the reference `content-auditor` compares against). This is the research's reliability lever for non-code review.
  This mapping is a new artifact: the target tiers, the per-source coverage phrasing, and the reference-material contract do not exist in the reviewers' own output, so they cannot be read from the agent definitions — only the source vocabularies can. The exact wrapper mechanism (a dispatch-instruction contract mirroring the existing one, versus a translating adapter agent) is left to `plan-implementation`; what is load-bearing here is that the mapping, the per-source coverage, the location rule, and the reference-material requirement exist and are applied before the gate.
