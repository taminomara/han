# Discovery Notes — Skill and Agent Review implementation

Single source of project context for the implementation team. Read this first; do not re-grep for what is here. This feature is a new Claude Code **skill** (markdown + optional bash scripts + `references/`), homed in `han-plugin-builder`, modeled on `han-coding/skills/code-review`. Downstream is `skill-builder` directly (no `plan-work-items`), so the plan must be concrete and must close OI-1 and OI-2.

## Tech stack / medium
- Skills are `SKILL.md` (YAML frontmatter + numbered prose steps) + optional `references/*.md` (domain rubrics/templates) + optional `scripts/*.sh` (deterministic detection, run via `${CLAUDE_SKILL_DIR}/scripts/…`) + optional `assets/`. No compiled code, no tests-as-code; "tests" are the triggering + functional checks from `success-criteria-and-testing.md`.
- Authoring rules live in `han-plugin-builder/skills/guidance/references/` (skill-building-guidance/, agent-building-guidelines/, plugin-entity-taxonomy.md, etc.).

## Base precedent: `han-coding/skills/code-review`
- **Layout:** `SKILL.md` + `references/{review-checklist.md, agent-finding-classification.md, template.md}` + `scripts/detect-review-context.sh`. This is the exact shape to mirror.
- **Frontmatter:** `arguments: size`, `argument-hint: "[size: small | medium | large]"`, `allowed-tools: Bash(git *), Bash(gh *), …, Read, Grep, Glob, Agent`. Context injection via `!\`find …\`` for CLAUDE.md/project-discovery.
- **Severity rubric structure** (`agent-finding-classification.md`): per-source CRIT/WARN/SUGG bands, each defined by concrete examples; size-based demotion governed centrally by SKILL.md Step 3.3; "when uncertain, prefer lower." This is the template for THIS skill's severity + bloat rubrics.
- **Untrusted-content mechanism:** Step 1.5 + Step 3.5 wrap third-party content in `----- BEGIN BRANCH CONTEXT (UNTRUSTED) -----` / `----- END … -----` markers before dispatch and tell the agent to disregard embedded directives. This is the concrete mechanism D8 must reuse for the artifact under review.
- **Detect-context script pattern** (`detect-review-context.sh`): emits `key: value` lines (git-available, branch, default-branch, changed-files-start/end); SKILL parses them. Degrades to `git-available: false` cleanly. Template for a guidance-location + git-context detector.
- **Adversarial-validator pass:** Step 7.4 — three verdicts (Confirmed/Partially-Refuted/Refuted), demote-don't-drop, drop only on concrete counter-evidence, overcorrection guard. THIS skill's step 8 inherits it.

## Home plugin: `han-plugin-builder`
- `plugin.json`: name `han-plugin-builder`, version `2.0.2`. Standalone, opt-in, depends on nothing, NOT bundled by the `han` meta-plugin. Also carries a `.codex-plugin/` dir (cross-tool).
- Skills present: `guidance`, `skill-builder`, `agent-builder`. New review skill joins them.
- Agents this skill dispatches (`han-core:junior-developer`, and any focused reviewers) live in `han-core` — so dispatch uses the qualified `han-core:<agent>` (agent-dispatch-namespacing rule). `han-plugin-builder` depends on nothing, so it does NOT currently declare a `han-core` dependency — **dependency gap to resolve** (the skill dispatches han-core agents but the plugin doesn't depend on han-core).

## Guidance-location facts (load-bearing for D9)
- Installed/bundled: `${CLAUDE_PLUGIN_ROOT}/skills/guidance/references/` (skill-builder/agent-builder use exactly this; `${CLAUDE_PLUGIN_ROOT}` resolves to `han-plugin-builder`).
- Vendored: `.claude/skills/plugin-guidance/references/` (written by `init-guidance.sh`).
- `init-guidance.sh` vendors exactly THREE skills (plugin-guidance, plugin-skill-builder, plugin-agent-builder) and, via `rewrite_skill`, `sed`-rewrites `${CLAUDE_PLUGIN_ROOT}/skills/guidance/references/` → `.claude/skills/plugin-guidance/references/`. Implication: a skill bakes in the `${CLAUDE_PLUGIN_ROOT}` path and vendoring retargets it — so which guidance copy is used is fixed at install/vendor time, not chosen at runtime. The runtime job reduces to an existence/completeness check (D9 halt-if-absent/partial/stale); the "prefer bundled when both resolve" logic may be unnecessary and is a D9 simplification candidate.
- Type split: `skill-building-guidance/` vs `agent-building-guidelines/` — the review resolves the type-appropriate subtree (D5/D9).

## Decision points the plan must close (beyond OI-1/OI-2)
- **Portability:** extend `init-guidance.sh` to vendor the review skill (so it runs in a vendored repo, guidance path auto-rewritten), or declare it han-only/bundled. Affects whether the vendored-guidance branch of D9 is ever reachable.
- **han-core dependency:** the skill dispatches `han-core:junior-developer`; `han-plugin-builder` must gain a `han-core` dependency, or the dispatch resolves only when han-core happens to be installed.
