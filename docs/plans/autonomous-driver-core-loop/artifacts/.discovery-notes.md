Single source of truth for project context. **Specialists: read this first; do not re-grep for what is already here.** Search further only for what your domain needs that is not covered below, and cite what you read.

## What "implementation" means here

This feature IS a new **Han skill** (a Claude Code plugin-suite slash command) plus **companion edits to one existing skill**. The "codebase" is the Han markdown plugin suite. Implementation means **authoring `SKILL.md` + `references/` files and editing existing skill files** — there is no compiled application code, no runtime service, no database. The skill it produces, however, *operates on any target project* at run time (it runs a build/verify/review/commit loop against whatever repo the operator points it at).

## Platform-capability findings (load-bearing — resolves the spec's one open mechanic)

Confirmed against current Claude Code docs (claude-code-guide agent, docs fetched 2026-06-30). These settle the dispatch topology D9 routed to `plan-implementation`:

1. **A sub-agent CAN spawn its own sub-agents — as of Claude Code v2.1.172, hard 5-level depth limit, fixed at spawn, not configurable.** So the review stage can run inside a dispatched sub-agent (depth 1) and fan out `code-review`'s panel (depth 2) without the panel entering the driver's context. This is the enabling capability for D9/D11's self-contained review. **Implication: the skill has a minimum-Claude-Code-version prerequisite (v2.1.172).** For a sub-agent to fan out, the `Agent` tool must be in its tools (present unless removed). **Provenance note:** this design work surfaced that Han's own agent guidance still carried the stale "subagents cannot spawn subagents" rule; that guidance was then updated (commit #100) to document the coordinator-dispatches-review-worker default-exception pattern. The plan and that guidance are consistent by construction (the guidance built off this work), so the guidance is an alignment reference, not independent evidence. The load-bearing evidence for the capability stays the platform behavior confirmed here (nesting as of v2.1.172) and spec D9.
2. **Three ways for a skill to dispatch a sub-agent that runs a named skill:** (a) the Agent/Task tool with a prompt instructing the sub-agent to invoke the skill by name (the Skill tool is available to sub-agents by default); (b) a custom agent definition with a `skills:` frontmatter list that **preloads the full skill content** at startup; (c) `--agents` JSON at launch. The Agent tool accepts a per-call `model`, which is how per-run build/fix model selection (D12) is wired.
3. **No schema-validated structured return exists for the Agent dispatch path.** A sub-agent's return is free-form text; the compact-report contract (D10) is **prompt-instructed, not enforced**. The driver must parse robustly and treat a malformed/incomplete report as untrustworthy → halt (aligns with D6 fail-closed).
4. **`skills:` preload frontmatter** works in file-based agent defs and `--agents` JSON; injects full content; cannot preload `disable-model-invocation: true` skills.

Sources: https://code.claude.com/docs/en/sub-agents.md (Spawn nested subagents; Preload skills into subagents), https://code.claude.com/docs/en/skills.md (Run skills in a subagent).

## Standards & conventions (the shape of the deliverable)

- **ADRs:** none (`docs/adr/`, `docs/architecture/` absent). **Coding-standards dir:** none. De-facto standards live in `CONTRIBUTING.md`, `docs/writing-voice.md`, and `han-plugin-builder/skills/guidance/references/` (skill-building-guidance, agent-building-guidelines, model-selection).
- **`SKILL.md` frontmatter:** `name`, `description` (multiline block scalar, doubles as the harness trigger, <1024 chars), `allowed-tools` (comma list; Bash perms per-prefix, NOT wildcards). Optional: `arguments`, `argument-hint`.
- **Directory layout:** `{plugin}/skills/{name}/` = `SKILL.md` + `references/` (0-N `.md`, referenced inline via relative links, read lazily) + optional `scripts/` (referenced with `${CLAUDE_SKILL_DIR}` paths).
- **Size precedent (SKILL.md line counts):** complex orchestration skills run **280-400 lines** (plan-implementation 287, tdd 277, code-review 398); focused single-loop ~120 (plan-work-items 119). Progressive disclosure: keep SKILL.md at orchestration altitude, push detail (formats, templates, checklists) into `references/`.
- **Add-a-skill checklist (CONTRIBUTING):** scaffold `{plugin}/skills/{name}/SKILL.md`; write frontmatter + body; copy the long-form template into `docs/skills/{name}.md` (verified layout is per-plugin: `docs/skills/han-coding/{name}.md`); add to the Skills Index (`docs/skills/README.md`, `## han-coding`); add to the catalog in root `CLAUDE.md`; update `.claude-plugin/marketplace.json` only if the plugin's component set changes (adding a skill to an existing plugin's own `skills/` dir needs no marketplace edit — verify).
- **Sub-agent dispatch convention:** launch via the `Agent` tool, one call per agent in a single message for concurrency; every skill carries "All sub-agents in this skill run on sonnet" — BUT this driver dispatches with an *explicit, capability-matched* model for build/fix (D12), operator-overridable, not a blanket sonnet rule. `code-review` uses `run_in_background: true` for its panel.

## Dispatched skills — behavior the driver must honor

- **`tdd`** (`han-coding/skills/tdd/`, 277 lines): default build skill. Runs **unattended** (no gate). **Does NOT commit** — writes prod+test files to the working tree. Emits a scope report + test list + final summary (test/lint/build status shown, and RED→GREEN observed-failure evidence from its load-bearing observed-failure gate). The driver's compact-report contract (STATUS / FILES / RED→GREEN / FINAL GATE / ESCALATION) maps directly onto what `tdd` already produces; the driver constrains the *format* by dispatch instruction (D10).
- **`code-review`** (`han-coding/skills/code-review/`, 398 lines): the review stage. Fans out a **panel of `han-core` agents** in parallel (`run_in_background: true`). Severity vocabulary Critical / Warning / Suggestion / YAGNI(advisory) / Security(SEC). Always-present output elements: the **Review Summary table** + the **Review Recommendation** (the verdict, e.g., a Critical yields a do-not-merge recommendation). The driver's condensed verdict (findings-by-severity complete at/above threshold + full-coverage attestation) maps onto the Recommendation + Summary counts; the driver instructs the review sub-agent to also **persist the durable full record** and return only the condensed verdict. `code-review` has no such compact mode today — the driver imposes it by dispatch instruction (D10); adding a native mode to `code-review` is **deferred** (spec Deferred section).
- **No new agents needed.** `code-review` supplies the reviewer panel from the existing `han-core` roster. `han-coding` has no `agents/` dir; if worker agent definitions were used (preload path), they would have to live in `han-core/agents/` per CONTRIBUTING — a heavier path than Agent-tool-with-prompt dispatch, which needs no new agents and supports per-call model.
